# 8체질 식단 일기 MVP 제품 요구사항 정의서

- 문서 상태: MVP 기획 개정

- 최종 개정일: 2026-10-20 (KST)
- 대상 플랫폼: 모바일 우선 반응형 웹
- 배포 형태: GitHub Pages에 배포하며 선택적 Firebase 로그인과 브라우저 로컬 데이터를 사용하는 프론트엔드 앱

## 1. 제품 개요

### 1.1 배경

8체질에 맞는 식생활을 실천하려면 일반적인 음식 목록을 보는 것만으로는 부족하다. 사용자는 실제로 무엇을 언제 먹었는지 기록하고, 그 음식이 자신의 체질에서 어떤 적합도로 분류되는지 식사 맥락 안에서 확인할 필요가 있다.

이 제품은 선택 사진을 포함한 식사 기록, 체질별 상세 섭생표, 영양 DB 기반 열량 계산과 복수 사용자용 공통 섭생 가이드를 결합한다. 사용자가 아침·점심·저녁·간식과 음식별 섭취량을 기록하면 기본 적합 등급·점수와 예상 열량을 자동으로 보여주고, 일간·주간·월간 분석에서 섭취 패턴을 돌아볼 수 있게 한다. 같은 기기에 등록한 두 사용자가 함께 먹을 때는 두 체질 모두 OO/O/△인 음식의 교집합을 제공한다.

### 1.2 목표 사용자

- 한의사 등 전문가에게 자신의 8체질을 안내받은 개인 사용자
- 식사 직후 휴대전화로 짧게 기록하려는 사용자
- 자신의 식사에서 체질별 권장·주의 음식의 비중을 확인하려는 사용자

### 1.3 핵심 사용 상황

1. 사용자는 식사를 마친 직후 기록 탭을 연다.
2. 아침·점심·저녁·간식 중 식사 유형을 선택하고, 원하면 사진을 촬영하거나 첨부한다.
3. 먹은 음식과 섭취량을 입력해 체질별 기본 적합도와 예상 열량을 확인한다.
4. 필요하면 메모 또는 코멘트를 덧붙여 저장한다.
5. 섭생표 탭에서 자신의 체질에 해당하는 상세 표와 체질 안내를 검색·필터링한다.
6. 함께 먹기 탭에서 사용자 두 명을 선택해 두 체질 모두 허용 범위인 음식 가이드를 확인한다.
7. 분석 탭에서 일간·주간·월간 섭생 점수, 등급별 그래프, 일간 열량 또는 주·월간 일평균 열량과 X·XX 음식을 확인한다.

### 1.4 사용자 가치

- 먹은 음식과 체질별 참고 적합도를 한곳에서 확인할 수 있다.
- 식사 사진과 식사 유형, 시각, 섭취량, 열량을 함께 남길 수 있다.
- 특정 기간에 어떤 등급의 음식을 얼마나 먹었는지 파악할 수 있다.
- 원문 출처가 명시된 체질별 상세 섭생표를 앱 안에서 탐색할 수 있다.
- 가족·동행인 두 명에게 공통으로 OO/O/△인 음식을 빠르게 찾을 수 있다.
- 체질을 변경해도 과거 기록을 새 체질 기준으로 다시 살펴볼 수 있다.

### 1.5 검증 목표

체질별 상세 섭생표, 식사 사진, 예상 열량과 기간별 섭생 분석이 실제 식사 회고에 유용한지 확인한다.

## 2. 제품 원칙

1. **빠른 기록:** 모바일에서 식사 직후 짧은 흐름으로 기록할 수 있어야 한다.
2. **명확한 정보:** 적합도는 기호, 점수, 설명을 함께 표시한다.
3. **로컬 우선:** 계정 없이 해당 브라우저 안에만 데이터를 보관한다.
4. **사용자 통제:** 기록 수정·삭제, 체질 변경, 전체 데이터 삭제가 가능해야 한다.
5. **비의료적 표현:** 진단, 치료, 효능 또는 섭취 지시로 오해될 표현을 사용하지 않는다.
6. **접근성:** 색상만으로 상태를 구분하지 않고 충분한 대비와 명시적 라벨을 제공한다.
7. **출처 투명성:** 섭생표와 영양 정보의 출처, 기준일과 데이터 버전을 사용자가 확인할 수 있게 한다.
8. **추정치 명시:** 열량은 음식과 섭취량에 따른 예상값이며 사진만으로 자동 판독하지 않는다.

## 3. MVP 범위

### 3.1 포함

- 최초 체질 설정 및 이후 변경
- 로컬 사용자 프로필 추가·수정·전환·삭제
- 아침·점심·저녁·간식 기록 생성
- 선택 사진, 식사 시각, 음식별 섭취량, 메모·코멘트 기록
- 음식 검색, 다중 선택, 직접 입력
- 음식별 기본 적합 등급과 점수 자동 표시
- 공공 영양 DB 기반 음식별·식사별·기간별 예상 kcal 계산
- 월간 달력, 날짜별 타임라인, 기록 상세·수정·삭제
- 8개 체질 안내 및 상세 섭생표 검색·분류·등급 필터
- 사용자 두 명의 공통 OO/O/△ 음식 가이드
- Google 계정을 이용한 선택적 Firebase 로그인
- 일간·주간·월간 분석
- 브라우저 로컬 저장 및 전체 데이터 삭제
- 출처·버전이 명시된 섭생표와 안전 안내

### 3.2 제외

- 자가 문진, 체질 추정 또는 진단
- 사용자의 주관적 적합도 평가
- 의료 상담, 치료 또는 섭취 추천
- 사진 AI 음식 인식, 사진 기반 자동 열량·분량 추정
- 식사·사진 데이터의 서버 저장 및 기기 간 동기화
- 데이터 내보내기·가져오기 및 백업·복원
- 칼로리 외 영양소 목표 관리, 알림, AI 추천, 소셜 기능, 전문가 공유

## 4. 적합도 체계

| 등급 | 점수 | 표시 문구 |
|---|---:|---|
| OO | 100점 | 가장 높은 적합 등급 |
| O | 75점 | 적합 등급 |
| △ | 50점 | 잦은 섭취 주의 |
| X | 25점 | 주의 |
| XX | 0점 | 가장 강한 주의 등급 |

### 4.1 적용 규칙

- 등급과 점수의 대응은 앱 전체에서 하나의 공통 상수로 관리한다.
- 출처 페이지의 `Δ` 표기는 앱 데이터에서 `△`로 정규화한다.
- 음식의 등급은 현재 선택된 체질과 기본 식품표의 조합으로 계산한다.
- 기록에는 계산 결과를 고정 저장하지 않는다. 체질이나 식품표가 바뀌면 현재 기준으로 다시 계산한다.
- 식품표에 없는 음식은 `적합도 정보 없음`으로 표시한다.
- 정보가 없는 음식은 평균 점수와 등급별 분포의 분모에서 제외한다.
- 등급은 기호와 점수를 항상 함께 표시하며, 상세 화면에서는 표시 문구까지 제공한다.

### 4.2 체질

MVP는 목양, 목음, 토양, 토음, 금양, 금음, 수양, 수음과 `체질 모름` 선택지를 제공한다. 앱은 사용자의 체질을 판단하지 않으며, 이미 안내받은 체질을 직접 선택하거나 모름으로 기록하게 한다. `체질 모름`에서는 식사 기록은 가능하지만 등급과 섭생 점수를 계산하지 않는다.

## 5. 핵심 사용자 흐름

### 5.1 최초 실행

1. 제품 목적과 로컬 저장 방식을 안내한다.
2. 기본 식품표가 검증 전 예시이며 의료적 판단 기준이 아님을 알린다.
3. 첫 사용자 이름을 입력하고 8개 체질 또는 `체질 모름`을 직접 선택한다. 이름 예시는 특정 사용자의 실명을 사용하지 않는다.
4. 선택을 저장하고 기록 화면으로 이동한다.

완료 조건: 첫 사용자 이름과 체질을 저장하고 필수 안내를 확인하기 전에는 기록 화면으로 진입하지 않는다.

### 5.2 식사 기록

1. 사용자가 `식사 기록`을 누른다.
2. 기본값으로 현재 시각이 입력되며 수정할 수 있다.
3. 음식 검색창에 음식명을 입력한다. 한 글자부터 대표명·별칭 부분 일치 자동완성 후보가 나타나며, 후보에는 음식명·분류·현재 체질 등급·점수를 함께 표시한다.
4. 후보를 선택하면 해당 음식이 `이번 식사에 추가한 음식` 목록으로 이동한다. 전체 식품을 체크박스로 한꺼번에 나열하지 않는다.
5. 검색 결과가 없으면 입력한 이름을 직접 음식으로 추가할 수 있으며 `적합도 정보 없음`과 `열량 정보 없음` 상태로 기록한다.
6. 선택한 음식마다 수량과 단위를 따로 입력한다. 예: `쌀 150g`, `쌀 1공기`, `사과 0.5개`, `쇠고기 120g`.
7. 아침·점심·저녁·간식 중 식사 유형을 선택한다. 같은 유형을 하루에 여러 번 등록할 수 있다.
8. 원하면 사진 한 장을 촬영하거나 첨부한다. 모바일 파일 입력은 카메라 촬영과 사진 보관함 선택을 지원한다.
9. g은 그대로 계산한다. 공기·개·인분은 공공 영양 자료에서 확인한 보통 크기 기본 중량을 자동 적용하고, 작음·보통·큼 또는 실제 g으로 수정할 수 있다. 검증된 기본 중량이 없는 음식만 실제 g 입력을 요청한다.
10. 등록 음식마다 기본 적합 등급·점수와 계산 가능한 경우 예상 kcal를 즉시 보여준다.
11. 선택적으로 메모 또는 코멘트를 입력한다.
12. 저장 후 해당 날짜의 타임라인과 분석을 갱신한다.

필수 입력은 식사 유형, 시각, 음식 한 개 이상과 음식별 섭취량이다. 사진과 메모는 선택 사항이다. 공백만 있는 음식명과 같은 식사 안의 중복 선택은 허용하지 않는다. 사진만으로 음식명·양·열량을 추정하지 않는다.

모든 식사 기록은 현재 활성 사용자 프로필에 귀속된다. 프로필을 전환하면 기록, 달력과 분석도 해당 사용자 데이터로 전환된다.

검색 자동완성은 대소문자·공백 차이를 무시하고 대표명과 별칭을 함께 검색한다. 선택된 음식은 후보에서 제외하고 동일 음식의 중복 추가를 막는다. 키보드로 후보 이동·선택·닫기가 가능해야 하며, 결과가 많으면 우선 8개만 표시한다. 데이터 사용 허가와 검수가 끝난 상세 섭생표의 모든 음식·음료 항목을 자동완성 원본으로 사용한다.

### 5.3 달력과 타임라인

- 달력의 날짜 셀에는 해당 날짜의 식사 기록 수를 표시한다.
- 적합도 정보가 하나 이상 있으면 그날의 평균 적합도 점수를 표시한다.
- 날짜를 선택하면 하단에 식사를 최신순으로 보여준다.
- 각 식사 카드에는 사진 썸네일, 식사 유형, 시간, 음식 목록, 총 예상 kcal와 메모 존재 여부를 표시한다.
- 타임라인의 등록 음식마다 기본 체질 등급과 점수를 표시한다.
- 미등록 음식에는 `정보 없음` 라벨을 표시한다.
- 카드를 선택하면 상세 화면으로 이동한다.

### 5.4 상세·수정·삭제

- 상세 화면에는 식사 유형, 시각, 사진, 음식별 섭취량·예상 kcal·등급·점수·설명, 총 예상 kcal와 메모·코멘트를 표시한다.
- 수정 시 기존 값을 불러오며 저장 후 모든 집계에 즉시 반영한다.
- 삭제 전 확인 절차를 제공한다.
- 삭제 취소 기능은 MVP에서 제공하지 않는다.

### 5.5 섭생표

- 현재 선택 체질의 요약 안내와 상세 섭생표를 한 화면에서 제공한다.
- 체질 요약에는 출처가 설명하는 기본 성향·성격적 경향·전통 이론상 신체 특징을 구분해 표시한다. 이는 성격 검사나 의학적 사실이 아니라 출처에 대한 요약임을 같은 영역에서 명시한다.
- 분류, 음식·생활 항목명, OO/O/△/X/XX 등급, 점수와 출처를 표시한다.
- 항목명 검색, 분류 필터, 등급 필터를 제공한다.
- 식사 기록의 음식 선택에는 음식·음료 범주의 항목만 사용하고, 활동·광물·약재 등 비식사 항목은 섭생표 탐색에만 표시한다.
- 다른 체질 표를 미리 볼 수 있지만 기록과 분석 계산은 설정된 내 체질을 기준으로 한다.
- 사용자가 제공한 8개 원문 HTML에서 목양·목음·토양·토음·금양·수양·수음 각 168개, 금음 167개로 총 1,343개 항목을 추출해 표시한다. 음식·음료로 분류한 총 1,087개 항목을 체질별 식사 기록 검색 원본으로 사용한다. 모든 데이터는 `source-extracted-unverified` 상태이며 전문가 검수와 이용 허가 확인 전 참고용으로 표시한다.

### 5.6 분석

- `일자`, `주간`, `월간` 기간 전환을 제공한다.
- 표시 항목은 식사 기록 수, 일간 총 예상 kcal 또는 주간·월간 일평균 예상 kcal, 평균 섭생 점수, 등급별 섭취 횟수·비율 그래프, 자주 먹은 음식, X·XX 음식 목록이다.
- 주간·월간 일평균 예상 kcal는 해당 기간의 계산 가능한 총열량을 식사 기록이 존재하는 고유 날짜 수로 나눈다. 기록이 없는 날짜는 분모에 포함하지 않고 `기록 N일 기준`을 함께 표시한다.
- ‘잘못된 음식’은 X와 XX 등급으로 정의하고 두 등급을 구분한다. △는 별도의 `잦은 섭취 주의`로 표시한다.
- 기록이 없으면 빈 상태와 기록 시작 버튼을 보여준다.
- 적합도 정보가 전혀 없으면 평균 대신 `계산할 수 없음`을 표시한다.
- 열량 정보가 없는 음식은 총열량에서 제외하고 누락 항목 수를 함께 표시한다.

### 5.7 함께 먹기

- 서로 다른 사용자 프로필 두 개를 선택한다.
- 각 체질의 상세 섭생표에서 두 사용자 모두 `OO`, `O` 또는 `△`인 음식·음료 항목만 교집합으로 생성한다.
- 한 사용자라도 `X`, `XX` 또는 적합도 정보 없음이면 공통 가이드에서 제외한다.
- 각 결과에는 음식명, 분류, A 사용자 등급·점수, B 사용자 등급·점수와 보수적 공통 점수를 표시한다.
- 보수적 공통 점수는 두 사용자 점수 중 낮은 값으로 계산한다.
- 결과는 보수적 공통 점수 내림차순, 두 점수 합 내림차순, 음식명 오름차순으로 정렬한다.
- OO/O 결과와 △ 포함 결과를 필터로 구분해 사용자가 더 보수적으로 볼 수 있게 한다.
- 채소·육류 등 카테고리 필터와 `공통 점수 높은 순`, `카테고리 순`, `음식 이름 순` 정렬을 제공한다.
- 이 가이드는 두 체질표의 기계적 교집합이며 식단 처방이나 안전 보장을 의미하지 않는다는 안내를 표시한다.

## 8. 집계 규칙

- 음식 평균 = 적합도 정보가 있는 음식 점수 합계 ÷ 해당 음식 수
- 식사 평균 = 해당 식사에 포함된 정보 있는 음식들의 산술 평균
- 일간·주간·월간 평균 = 기간 내 정보 있는 모든 음식 점수의 산술 평균
- 표시 평균은 계산 후 반올림한 정수 점수로 보여준다.
- 등급별 분포는 정보 있는 음식의 섭취 건수를 기준으로 한다. 동일 음식을 여러 번 먹으면 각각 한 건으로 집계한다.
- 자주 먹은 음식은 기간 내 이름별 섭취 건수 내림차순으로 정렬하고, 동률이면 최근 섭취 시각 내림차순으로 정렬한다.
- 주의 음식은 X와 XX 등급으로 정의하며 두 등급을 구분해 표시한다.
- 음식 예상 kcal = `kcalPer100g × resolvedGrams ÷ 100`이며 소수 첫째 자리에서 반올림해 정수로 표시한다.
- 식사와 일간 총 예상 kcal는 열량 계산이 가능한 음식들의 합이다. 주간·월간은 같은 합을 해당 기간의 기록이 있는 고유 날짜 수로 나눈 일평균 예상 kcal를 기본 표시한다. 누락 음식이 있으면 완전한 총량으로 오해하지 않도록 누락 개수를 표시한다.
- 섭생 점수는 섭취량이나 kcal로 가중하지 않고, 기간 내 적합도 정보가 있는 음식 선택 건별 점수의 산술 평균으로 계산한다.
- 주간 범위는 월요일 00:00부터 일요일 23:59:59까지, 월간 범위는 해당 달의 첫날부터 마지막 날까지 사용자 현지 시간으로 계산한다.

- 앱에서 사용하는 주요 응답 필드는 `foodCd`, `foodNm`, `enerc`, `nutConSrtrQua`, `foodSize`, `srcNm`, `crtrYmd`다.
- 인증키는 저장소, PRD, 브라우저 저장소와 클라이언트 번들에 넣지 않는다. 로컬 환경변수 `NUTRI_API_KEY`로 동기화 스크립트에만 전달한다.
- 생성 캐시는 원본 식품코드, 식품명, 기준량, kcal, 식품중량, 출처명, 데이터기준일과 동기화 시각을 보존한다.
- API 실패 시 마지막으로 성공한 캐시를 유지하며 앱은 캐시 버전과 최신 동기화 실패 상태를 표시한다.
- 데이터 항목마다 출처 식별자, 기준량, 기준 중량, 열량, 버전·기준일을 보존한다.
- 체질 섭생표 항목과 영양 DB 항목은 별도 ID를 유지하고 명시적인 매핑 테이블로 연결한다.
- 이름이 같아도 조리 상태나 제품이 다르면 자동 병합하지 않는다.

## 10. 안전 및 콘텐츠 정책

- 온보딩과 설정에 다음 의미의 안내를 지속적으로 제공한다: 이 앱은 식사 기록용이며 의료 진단·치료·섭취 지침을 제공하지 않는다.
- 식품표는 검증 전 예시 데이터임을 적합도 표시 주변과 설정에서 확인할 수 있어야 한다.
- 외부 섭생표를 표시할 때 출처와 확인일을 함께 제공하고 앱의 점수는 원문 등급을 수치화한 기록용 지표임을 명시한다.
- kcal는 선택한 영양 항목과 입력량으로 계산한 예상치이며 실제 섭취량과 다를 수 있음을 표시한다.
- `먹어야 한다`, `치료한다`, `예방한다`, `위험하다`처럼 확정적인 의료 표현을 사용하지 않는다.
- 실제 사용자 대상 출시 전 한의학 분야 전문가의 검수, 데이터 출처, 버전과 수정 이력을 마련한다.

## 11. 비기능 요구사항

- 모바일 우선으로 설계하되 데스크톱에서도 기능 손실 없이 반응형으로 동작한다.
- 최신 주요 브라우저의 최근 안정 버전을 지원 대상으로 한다.
- 핵심 흐름은 키보드만으로도 조작 가능해야 한다.
- 모든 입력에 연결된 라벨을 제공하고 상태 변화는 보조 기술이 인식할 수 있어야 한다.
- 네트워크 연결 없이도 이미 로드된 앱과 로컬 기록을 사용할 수 있는 구조를 지향하되, 설치형 PWA와 오프라인 캐시는 MVP 필수 범위에 포함하지 않는다.

## 12. 수용 기준

1. 최초 사용자가 체질을 선택하고 식사 기록 화면에 진입할 수 있다.
2. 한 식사에 서로 다른 등급의 음식 여러 개를 저장할 수 있다.
3. 등록 음식에는 선택 체질에 맞는 등급, 점수, 설명이 정확히 표시된다.
4. 미등록 음식은 오류 없이 정보 없음으로 저장·표시된다.
5. 타임라인의 모든 등록 음식에 기본 등급과 점수가 함께 표시된다.
6. 수정·삭제 결과가 달력, 타임라인과 분석에 즉시 반영된다.
7. 일간·주간·월간 평균과 등급 분포가 집계 규칙에 맞는다.
8. 체질 변경 후 기존 식사 데이터는 유지되고 적합도와 집계만 다시 계산된다.
9. 새로고침 후에도 같은 브라우저에서 설정과 기록이 유지된다.
10. 모바일과 데스크톱에서 동일한 핵심 기능을 사용할 수 있다.
11. 적합도를 색상 없이도 기호, 점수와 텍스트로 이해할 수 있다.
12. 식품표의 검증 상태와 의료 면책 내용을 사용자가 확인할 수 있다.
13. 하단 내비게이션이 기록·섭생표·함께 먹기·분석의 네 탭으로 구성된다.
14. 아침·점심·저녁·간식 기록에 선택 사진, 시각, 음식별 양과 선택 메모를 저장할 수 있다.
15. 음식별 예상 kcal와 일간 총열량, 주간·월간의 기록일 기준 일평균 열량이 영양 DB 기준으로 정확히 계산된다.
16. 섭생표 탭에서 8개 체질의 안내와 상세 표를 검색하고 분류·등급으로 필터링할 수 있다.
17. 일간·주간·월간 분석에서 섭생 점수, 등급별 횟수·비율 그래프, 기간에 맞는 예상 kcal, X·XX 음식과 △ 음식이 구분되어 표시된다.
18. 섭생표와 영양 데이터의 출처, 확인일과 버전을 확인할 수 있다.
19. 같은 기기에 사용자 프로필을 두 개 이상 만들고 각 기록과 분석을 분리할 수 있다.
20. 두 사용자 모두 OO/O/△인 음식만 함께 먹기 결과에 포함되고 X/XX/정보 없음 항목은 제외된다.
21. 함께 먹기 결과에 각 사용자 등급과 두 점수 중 낮은 공통 점수가 표시된다.
22. API 인증키가 브라우저 번들이나 버전 관리 파일에 포함되지 않는다.
23. 영양 API 동기화 실패 시 마지막 정상 캐시를 보존하고 오류 원인을 명확히 보고한다.
24. 식사 기록에서 `사과`와 같은 음식명을 입력하면 대표명·별칭 부분 일치 후보가 등급·점수와 함께 표시되고, 선택한 음식만 섭취량 입력 목록에 추가된다.
25. 검색 결과가 없는 음식은 직접 추가할 수 있고 적합도·열량 정보 없음으로 명확히 구분된다.
26. 음식마다 수량과 단위를 독립적으로 입력하며, 검증된 기본 중량은 자동 적용하고 작음·보통·큼 또는 실제 g으로 수정할 수 있다.
27. 8개 체질 섭생표에서 원문 기준 총 1,343개 전체 항목을 분류·등급·점수와 함께 검색·필터링할 수 있다.
28. 체질을 설정하면 해당 체질 표의 음식·음료 항목을 대상으로 `사과` 같은 부분 일치 검색 결과를 보여준다.
29. 기록 탭과 분석 탭 모두 월간 달력을 제공하며 선택한 날짜가 기록 시각·타임라인·분석 기준에 반영된다.
30. `체질 모름` 프로필은 식사를 기록할 수 있고, 적합도 정보가 없는 상태를 오류나 0점이 아닌 `정보 없음`으로 표시한다.
31. 상단 `+` 버튼으로 앱 내부 사용자 추가 창을 열어 이름과 체질을 저장할 수 있다.
32. 사진 없이도 식사를 저장할 수 있고 모바일에서는 사진 입력 시 카메라 또는 보관함을 사용할 수 있다.
33. `개` 등 비중량 단위는 검증된 기본 중량을 자동 적용하고 사용자가 실제 중량으로 수정할 수 있으며, 기준 중량이 없는 음식만 실제 g 입력을 요구한다.
34. 함께 먹기에서 카테고리 필터와 공통 점수·카테고리·이름 정렬이 동작한다.
35. Firebase가 설정된 환경에서 이메일·Google 로그인과 로그아웃이 동작하고, 설정되지 않은 환경에서는 로컬 모드를 유지한다.
36. `main` 브랜치 변경 시 품질 검사를 통과한 React 앱이 GitHub Pages에 배포되고, Firebase 설정값은 저장소에 노출되지 않는다.

## 13. 성공 판단

초기 사용성 검증에서는 사용자가 별도 설명 없이 로그인 또는 로컬 모드를 선택하고, 프로필과 체질 또는 `체질 모름`을 설정하고, 음식별 섭취량과 선택 사진을 포함한 식사를 기록하며, 네 개의 탭에서 상세 섭생표·공통 음식 가이드·일간·주간·월간 분석을 찾을 수 있는지 확인한다. 적합도 정보의 정확성은 사용 허가와 전문가 검수를 거친 데이터로 별도 평가하고, 열량은 영양 DB 항목 선택과 섭취량 입력 정확도를 함께 검증한다.
